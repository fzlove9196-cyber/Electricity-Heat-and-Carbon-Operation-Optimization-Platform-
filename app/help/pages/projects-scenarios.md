# 项目、多场景与发布版本

> **目的**：用「项目 → 场景草稿 → 不可变版本」管理方案，保证每次求解的输入可追溯。
> **前置条件**：服务运行；首次启动会自动生成模板与资源种子。
> **界面入口**：① 资源与建模 → 📁 项目与场景。状态：【已实现】。

[▶ 打开此功能：项目与场景](/?view=foundation)

## 核心概念

| 对象 | 能否修改 | 说明 |
|---|---|---|
| 项目 | 名称与资料引用可改 | 资料引用可填标题 / URL / 知识库文档 ID；`pending` 记录待确认项 |
| 场景（草稿） | 可改（带版本号乐观锁） | 一个项目可有多套场景；有待确认项时禁止发布 |
| 发布版本 v1、v2… | **不可变** | 发布时把绑定资源展开进模型并计算摘要 hash；无覆盖 / 删除接口 |
| 冻结任务 | 快照不可变 | 见 [版本化仿真任务](/help/versioned-tasks) |

## 页面上的五张卡片

### 1 · 项目与资料

1. 输入项目名 → **创建项目**。
2. 资料 JSON（`documents` / `pending`）可登记工程资料引用和待确认内容 → **保存项目名称与资料引用**。
3. **注意：PDF 不会自动可靠生成拓扑。** 资料只做引用登记，不解析接线图。

### 2 · 创建独立场景

| 按钮 | 作用 |
|---|---|
| 从模板新建 | 复制所选模板，按「新建场景时间轴」JSON 建草稿 |
| 复制所选已发布版本 | 以顶部所选版本为起点建新场景，保留出处 |
| 新建年度CFE独立场景 | 见 [年度 CFE 采购](/help/annual-cfe) |
| 新建GPU离散控制独立场景 | 见 [GPU 功率帽与 SLA](/help/gpu-sla) |
| 新建电网反馈独立场景 | 见 [电网再出清与边际碳](/help/grid-feedback) |
| 将当前旧会话导入为场景 | 把对话工作台当前会话的模型纳入项目（不会自动迁移其他会话） |
| 导入结构化场景JSON | 导入完整场景 JSON 文件，会严格校验 |

### 3 · 场景草稿与模型编辑

| 按钮 | 作用 |
|---|---|
| 签出草稿 → 拓扑/配置编辑 | 生成**独立会话副本**，可在拓扑编辑器、参数表、配置构建器、对话中修改 |
| 当前会话模型 → 写回场景草稿 | 把会话中修改后的模型写回草稿；会实体化当前参数并**解除旧绑定**（防止库参数覆盖手改） |
| 显式展开为15分钟草稿 | 把 24 点草稿 sample-and-hold 成 96 点（有资源绑定时须先实体化，否则拒绝） |
| 迁移次目标 / 写入编辑器 | `off`（默认）或 `lexicographic_gross`（锁主目标后最小化 gross 迁移量） |
| 保存编辑器草稿 | 保存下方「完整草稿JSON」的修改 |
| 校验与展开 | 展开绑定、执行静态校验，列出错误与告警 |
| 发布不可变版本 | 生成新版本；存在待确认项或错误时拒绝 |

> 草稿 JSON 的未保存编辑会跨页面保留；切换项目 / 场景时会先确认。

### 4 · 绑定通用数据与设备版本

## 典型操作：修改模型并发布新版本

1. 卡片 3 点 **签出草稿 → 拓扑/配置编辑**，进入拓扑页修改（例如把 DC_A 的 PUE 从 1.35 改为 1.40）。
2. 顶部出现「会话修改尚未写回草稿」「旧结果已过期」提示。
3. 回到项目页，点 **当前会话模型 → 写回场景草稿**。
4. **校验与展开** → **发布不可变版本**（得到 v2）→ 到任务页用 v2 建新任务。v1 的任务和结果保持不变。

![修改后提示未写回与结果过期](/help/img/r1106-expired.png)

## 常见问题

- **「草稿已被其他操作修改，请刷新后重试」/「草稿版本冲突」**：草稿的 revision 已变化，刷新页面后重做修改。
- **「存在待确认项，先确认再发布」**：清空或处理草稿 `pending` 中的条目。
- **「模型dt/长度与场景时间轴不匹配」**：模型的 `dt_hours` 与时间轴 `step_minutes`/`length` 必须一致（60/24 或 15/96）。
- 发布**不是工程安全认证**：静态校验通过仍可能动态不可行，交流校核与压力验证仍需执行。
