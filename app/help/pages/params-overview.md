## 读懂参数表的列

| 列 | 含义 |
|---|---|
| 字段 | JSON 中的字段名（路径如 `data_centers.0.pue` 表示第 1 个数据中心的 PUE） |
| 单位 | 统一用 MW / MWh / 元 / tCO2 等；p.u. 表示 0~1 比例 |
| 默认值 | 未填写时引擎使用的值。**默认值均为合成示例或假设，须按场景校准** |
| 合理范围 | 参数表中显示的提示范围（取自代码），超出时标红 |
| 不合理时 | 系统的实际处理方式，见下 |

## 不合理时系统怎么处理

| 处理 | 含义 | 举例 |
|---|---|---|
| **拒绝** | 类型 / 枚举错误或硬约束违反：参数表修改失败、草稿不能保存或发布、任务不能创建、对话求解报错 | SOC 下限 > 初始 SOC；`dt_hours` 填 0.5；PUE 拼错字段名（项目草稿） |
| **警告** | 参数表标红「超出合理范围」或校验告警，**仍允许运行**，请自行判断 | PUE = 3.5；储能时长 20 h；风冷单柜 30 kW |
| **运行时失败** | 静态校验通过，但求解不可行 / 超时，任务记为 failed，不伪造结果 | 可靠电源不足、连续任务窗口不够 |
| **回滚** | 在项目签出会话中做了非法修改，修改被撤回 | 拓扑编辑后出现错误 |

**项目草稿比旧式会话更严格**：未知字段拒绝；PUE < 1、IT 容量 ≤ 0、储能效率不在 (0, 1]、温度边界顺序错误、热模型参数非正、非有限数值等在项目草稿 / 版本化任务中直接拒绝。在未纳入项目的旧式会话中，其中部分项只在参数表标红或作为拓扑告警出现。各分篇「不合理时」一列标注的「拒绝（项目）」即指这一类。

## 参数来源标签

② 输入参数中每个参数都带来源：用户指定、智能体推断、默认值、案例假设、公开资料；来自资源绑定的参数会写明「固定资源 名称 r版本 (ID)；来源；工况」。核对时请特别关注「默认值」和「智能体推断」。

## 修改参数的三种方式

1. **参数表**（推荐）：直接改值，系统立即重新校验；失败会提示「修改后校验失败：…」，并保持原值。
2. **拓扑编辑器**：点元件改表单，适合结构类参数。
3. **JSON**：项目草稿 JSON 或场景表单 JSON，适合批量与高级字段。
