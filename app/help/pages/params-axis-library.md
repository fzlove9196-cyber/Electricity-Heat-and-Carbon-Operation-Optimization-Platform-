# 时间轴与资源字段

> **目的**：正确填写项目场景时间轴和通用数据资源。
> **前置条件**：知道数据的地点、年份、时区、起始时间、步长。
> **界面入口**：项目页「新建场景时间轴」与「完整草稿JSON」的 `axis`；资源库 JSON 编辑器。

[▶ 打开此功能：项目与场景](/?view=foundation)

## 场景时间轴 `axis`（日调度）

时间轴**只允许**以下 6 个字段，缺一不可，多了也拒绝。

| 字段 | 含义 | 单位 / 格式 | 约束 | 不合理时 |
|---|---|---|---|---|
| `location` | 地点名称 | 文本 | 非空；绑定时与资源一致 | 拒绝 / `axis_mismatch` |
| `year` | 年份 | 整数 | 等于 `start` 的年份 | 拒绝「year 与 start 不一致」 |
| `timezone` | 时区 | IANA 名称，如 `Asia/Shanghai` | 必须是有效 IANA 时区 | 拒绝「无效IANA时区」 |
| `start` | 起始时刻 | ISO 8601 带偏移，如 `2024-07-01T00:00:00+08:00` | 必须带偏移，且偏移与时区一致；必须是**当地零点** | 拒绝 |
| `step_minutes` | 步长 | 分钟 | 60 或 15 | 拒绝 |
| `length` | 点数 | 个 | 与步长配对：60→24、15→96 | 拒绝「不能自动截断」 |

此外，模型的 `dt_hours`（1 或 0.25）必须与 `step_minutes`/60 一致、步数与 `length` 一致，否则拒绝「模型dt/长度与场景时间轴不匹配」。示例：

```json
{"location": "中卫", "year": 2024, "timezone": "Asia/Shanghai",
 "start": "2024-07-01T00:00:00+08:00", "step_minutes": 60, "length": 24}
```

## 独立模式的时间轴

| 模式 | 规则 |
|---|---|
| 年度 CFE | `timezone` 必须 `UTC`，`step_minutes` 60；`year` = 气象年；全年模式从 1 月 1 日 00:00 UTC 起 8760（闰年 8784）点；benchmark 模式 1–168 点 |
| 电网反馈 | `UTC` 整点，60 分钟，1–168 点；与源输入起点、长度完全一致 |
| GPU | 起点带时区且对齐时间槽；步长 15 或 60 分钟；1–96 步；`year`/`step_minutes`/`length`/`start` 与模型一致 |

## 时间序列资源（气象 / 电价 / 碳 / 负荷）

| 字段 | 含义 | 约束 | 不合理时 |
|---|---|---|---|
| `name` | 资源名称 | 必填 | 拒绝「缺少 name」 |
| `kind` | `weather` / `price` / `carbon` / `load` | 必填 | 拒绝「未知资源类型」 |
| `source` | 来源（URL、文件、说明） | 必填 | 拒绝 |
| `applicability` | 适用工况 | 必填 | 拒绝 |
| `unit` | 单位 | `degC` / `CNY/kWh` / `tCO2/MWh` / `MW`，与 kind 对应 | 拒绝「单位必须 …」 |
| `axis` | 时间轴 | 同上表规则 | 拒绝 |
| `values` | 数值数组 | 点数 = `axis.length`；有限、无缺失、非布尔；碳 / 负荷 ≥ 0；温度 −90 ~ 65 | 拒绝 |
| `timestamps` | 可选逐点时间戳 | 与时间轴逐点一致，无重复 / 跳点 | 拒绝 |
| `previous_id` | 修订时的前一版本 ID | 类型必须相同 | 拒绝「版本类型不可改变」 |
