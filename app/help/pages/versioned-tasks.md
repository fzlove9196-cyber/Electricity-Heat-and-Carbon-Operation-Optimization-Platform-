# 版本化仿真任务：冻结、运行、追溯与重跑

> **目的**：对已发布版本创建「冻结任务」，用原求解引擎计算，并完整保存输入、来源、代码与求解器标识，支持历史恢复和按原快照重跑。
> **前置条件**：顶部「任务输入版本」已选中一个**已发布版本**（不读取当前会话和未保存草稿）。
> **界面入口**：② 仿真优化 → ▶ 版本化仿真任务。状态：【已实现】（日调度 24 点 / 96 点；8760 原寻优未纳入，见 [年度寻优与多目标](/help/annual-optimization)）。

## 创建并运行

1. 任务名称（可选）。
2. **目标**：

| 选项 | 值 | 含义 | 要求 |
|---|---|---|---|
| 运行成本最优 | `cost` | 碳权重显式置 0 | — |
| 成本 + 加权碳成本 | `weighted_carbon` | 目标 = 成本 + w × 碳价 × 排放 | 填「碳权重」w ≥ 0（默认 1） |
| 福利出清（显式任务报价） | `welfare` | 最大化接纳任务价值 − 成本 | 场景必须有任务 `jobs`，每个任务给出 `value_cny_mwh`，且碳权重为 0 |

   **纯碳目标会被拒绝**：「请使用 weighted_carbon 并明确权重」——系统不会用大权重成本冒充纯碳最优。纯碳或 Pareto 多目标请用仿真工作台的寻优功能。

3. **求解器软限时（秒）**：0 < 值 ≤ 600，默认 120。只计算求解器本身，排队、建模、导出另计。
4. **交流校核**：默认勾选；独立模式（年度 CFE / 电网反馈 / GPU）与 `paper_abstract` 网络域必须关闭（独立模式下页面会自动取消勾选并禁用，目标只允许 cost，软限时自动设为 600）。
5. 点 **创建冻结任务** → 列表中选中 → **运行所选任务**。

## 运行状态与执行域

- 状态：`ready → running → completed / failed`。**每个任务只能运行一次**。
- 页面每 3 秒只读刷新「Pyomo执行域：空闲 / 持有者 / 等待队列」。日调度、年度 CFE、VCC、三级运行的 Pyomo 管线按 FIFO 排队，避免并发串扰；排队不计入软限时。
- 失败如实记为 failed：不回退旧计划、不自动换算法 / 重试、不生成伪结果。
- 服务重启时正在运行的任务会被标为 failed（不自动续算），请用「按原快照创建重跑」。

## 追溯与导出

| 按钮 | 作用 |
|---|---|
| 查看当时模型与结果 | 从存储恢复为**新的历史展示副本会话**，可进入结果页 / 拓扑 / 三级运行；不借用当前会话 |
| 按原快照创建重跑 | 生成新任务（`rerun_of`），使用原冻结输入，不重新解释资源库 |
| 下载任务/输入/结果JSON | 下载任务记录 |

「冻结输入、来源、求解信息与结果」区显示完整快照：版本、绑定与资源内容、`input_hash`、`code_hash` / `execution_code_hash`、求解器版本（pyomo / highspy / pandapower）。全年数组只预览长度，完整内容见 ZIP。

年度 CFE、电网反馈、GPU 任务完成后，页面会显示对应结果卡片（CFE / Grid / GPU 结果区），并可下载正式 ZIP（`/api/foundation/tasks/{id}/export.zip`）。详见各模式篇章。

## 常见拒绝

- 「先发布并选择场景版本」：顶部没有选中已发布版本。
- 「冻结输入摘要不匹配，拒绝求解」/「场景版本内容与摘要不一致」：数据被篡改或损坏，请重新发布。
- 「任务已执行/正在执行；历史重跑请创建新任务」。
- 「求解时间须在0~600秒」「未知求解配置」。
