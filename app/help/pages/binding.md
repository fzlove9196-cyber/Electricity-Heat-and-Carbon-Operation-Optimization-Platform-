# 数据绑定与时间轴对齐

> **目的**：把资源库中的固定版本数据接入场景草稿，并保证时间轴、单位严格一致。
> **前置条件**：已有场景草稿；资源库中有对应版本。
> **界面入口**：① 资源与建模 → 📁 项目与场景 → 卡片「4 · 绑定通用数据与设备版本」。状态：【已实现】。

[▶ 打开此功能：项目与场景](/?view=foundation)

## 绑定目标规则

| 资源 | 绑定目标 | 求解前覆盖什么 |
|---|---|---|
| 气象 | 场景公共信号 | 默认 / 已有区域的室外温度 |
| 电价 | 场景公共信号 | 场景电价，同时更新显式外网价格 |
| 碳 | 场景公共信号 | 实际区域的平均 / 边际碳强度 |
| 负荷 | 指定数据中心（必选） | 目标数据中心的 `interactive_mw` |
| 设备模型 | 对应类型的指定设备 | 目标设备参数（含分段功率曲线、热性能），并重新校验 |

## 操作步骤

1. 第一个下拉选资源版本，第二个下拉选目标。下方预览会显示双方时间轴与逐字段差异。**只选下拉框不会保存。**
2. 首次绑定该类数据：点 **新增绑定并校验**。
3. 该类已有绑定：点 **替换同类绑定并校验**（同类已存在时「新增」会被拒绝，不会自动叠加或覆盖）。
4. 若以所选数据的时间轴为准：先勾选「同时按所选数据设置草稿时间轴」再绑定。确认后与绑定原子保存；若其他已绑定数据与新时间轴冲突，**整体拒绝**。
5. 「已保存绑定」列表才是真正保存的结果。删除绑定目前需在草稿 JSON 中完成。

## 时间轴校验字段

| 字段 | 规则 | 不匹配时 |
|---|---|---|
| `location` | 与草稿一致；跨区请独立建场景 | `axis_mismatch`，逐字段列出期待值与实际值 |
| `year` | 一致 | 拒绝 |
| `timezone` | IANA 时区一致（如 `Asia/Shanghai`），不做时区转换 | 拒绝 |
| `start` | 时间戳一致（含偏移） | 拒绝 |
| `step_minutes` | 60（24 点）或 15（96 点），并与模型 `dt_hours` 一致 | 拒绝，不隐式重采样 |
| `length` | 与模型步数一致 | 拒绝，不截断或补值 |

设备模型没有时间轴，不参与时间轴对齐（勾选对齐时会提示不能对齐）。

## 注意

- 失败不保存、不回退示例数据，历史版本不变。
- 写回会话模型到草稿时会**解除旧绑定**（实体化参数），需要继续参数化绑定时请重新绑定。
- 年度 CFE / 电网反馈 / GPU 独立模式不支持绑定 24h 公共信号或日设备，会显式拒绝。
