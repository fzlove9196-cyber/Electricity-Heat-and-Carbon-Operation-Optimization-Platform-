# 时间步：1 小时与 15 分钟

> **目的**：正确使用 15 分钟时间步，理解哪些路径会**显式拒绝**。
> **前置条件**：项目场景草稿（推荐），或会话场景。
> **界面入口**：① 项目与场景 → 卡片 3「显式展开为15分钟草稿」；草稿 JSON 中的 `dt_hours`。状态：【部分实现】。

[▶ 打开此功能：项目与场景](/?view=foundation)

## 支持矩阵

| 路径 | 1h（24 点） | 15min（96 点） |
|---|---|---|
| 日调度（工作台 / 版本化任务） | ✅ | ✅ |
| 整数连续任务（日调度内） | ✅ | ✅ |
| GPU 离散控制（opt_gpu） | ✅ | ✅（1–96 步） |
| 三级运行 | ✅ | ❌ 报错「三级运行 尚不支持15min/整数连续任务」 |
| VCC 虚拟容量 | ✅ | ❌ 必须关闭 |
| 交易沙盘 | ✅ | ❌「市场沙盘仅支持1h」 |
| 年度投资 / 代表日寻优 | ✅ | ❌「禁止隐式按1h」 |
| 年度 CFE、电网反馈 | ✅（仅 1h） | ❌ |

**系统不会把 15 分钟数据暗中当作 1 小时计算。** 不支持的组合一律报错。

## 怎样得到 15 分钟草稿

1. 从 24 点 / 60 分钟场景开始。若草稿有资源绑定，先写回 / 实体化（否则展开会被拒绝）。
2. 点 **显式展开为15分钟草稿**：把所有逐时曲线（电价、负荷、出力系数、温度、热需求、碳强度等）按 sample-and-hold 复制 4 次；MWh、物理小时截止期不变；`dt_hours` 变为 0.25，时间轴变为 `step_minutes=15`、`length=96`。
3. 检查编辑器 → **保存编辑器草稿** → 校验 → 发布。展开只写入编辑器，**不自动修改已保存对象**。

也可以在草稿 JSON 中直接提供完整的 96 点数据。

## 守恒规则

- 能量 = 功率 × Δt（Δt = 1 或 0.25 h）：SOC、任务能量、发电上限、迁移、线路费、电价 / 碳 / DR 分账都乘 Δt；峰需量费不乘 Δt。
- 爬坡（MW/h、K/h）按 Δt 换算；热管延迟 1 h = 15 分钟下 4 步。
- 任务的 `release` / `deadline`、DR 的 `start` / `end` 是**物理小时**，必须对齐 Δt（例如 15 分钟下可以写 8.25，不能写 8.1）。
- 1h 与 15min 最优值**不要求相等**（离散化与可决策网格不同）。
- 15min 导出表统一 `step / hour / duration_h`（hour = step × 0.25）。
