# 产品基础层实施与验收

## 实施前核查与设计（2026-11-06，北京时间）
现有 FastAPI 单体、Pydantic Scenario、Pyomo/HiGHS 联合调度及 pandapower 校核保留；市场沙盘路由不改。现有拓扑编辑/配置构建器基于会话；缺少模型库。A01 电池调节方向已有修复及 test_rt_rules_battery_sign_tracks_signal 回归，需纳入全量测试。

新增独立 SQLite 本地产品基础层：Project → Scenario（可变 draft + 不可变 published version）→ Task（不可变展开输入快照）→ 结果/独立会话/artifacts。模板和通用资源采用只追加版本，新场景复制模板；绑定引用确定版本并将其内容与 hash 冻结。既有会话不自动迁移，用户显式导入或签出副本编辑。工程资料仅保存来源/待确认项，结构化 JSON 可导入，不声称 PDF 自动建模。

## 实施顺序
1. 事务存储、严格校验与资源/模板种子；2. 场景发布与数据/设备绑定展开；3. 任务调用原求解与结果追溯/重跑；4. 六域上下文和完整 UI；5. 新测试及中卫/韶关/乌兰察布完整链验证，全量 pytest。

## 校验边界
本轮版本任务支持原日调度的 24 点、1 小时步长；不会静默截断 8760 数据或自动填补缺失。气象/电价/碳/负荷必须指定地点、年份、IANA 时区、起始时间、单位、来源及工况；绑定必须匹配场景时间轴（跨区需独立建场景，禁止默默转换）。校验参数物理边界、引用、长度、拓扑电压/孤岛，告警与错误分开。发布不是工程安全认证，交流校核与压力验证仍需执行。

## 兼容与安全
旧路由/会话继续可用；只在显式签出的会话建立项目上下文。会话编辑不改历史版本，先写回草稿再发布。已发布版本、模板版本、资源版本无覆盖/删除 API。任务只执行本地仿真，不真实交易，不读凭据。UI 检查由主助手另行安排，禁止 Shell 浏览器截图。

## 已落地的数据对象与执行语义
- `app/foundation/store.py`：本地 `data/foundation.sqlite3`，事务写入与乐观草稿版本检查。已发布场景/模板/资源无更新与删除接口；完成任务的输入和输出也不可覆盖。
- `service.py`：模板复制、引用固定资源版本、静态校验、发布时展开、输入规范化哈希、代码树与 Pyomo/HiGHS/pandapower 版本标识、调用原求解、完整结果序列化、历史重跑。服务重启把中断任务标为失败，不偷偷续算。
- `api.py`：`/api/foundation` 下项目、场景、版本、模板、资源、任务；旧路由保持兼容。catalog 返回任务摘要，详情按需读。
- `foundation.js`：顶部项目/场景/版本上下文；资源与建模域下项目起点、模板/数据设备库；仿真域下版本化任务。原对话、六步透明工作流、配置构建器、拓扑、三级、market 保留。

### 版本与来源
草稿可改，发布只追加；模型、资源内容、来源、单位、工况、固定版本/hash 随发布和任务保存。复制模板/版本会保留出处。项目支持资料引用和待确认项，不解析 PDF 接线；结构化场景 JSON 导入会做校验。任务另保存项目资料引用和场景复制来源，输入快照也写入运行产物 `input_snapshot.json`。

### 真实求解接入（非元数据 CRUD）
任务从选定场景版本复制展开模型，按显式目标应用 `carbon_weight`，调用原 `run_dispatch` → `sdco_engine.solve`（Pyomo/HiGHS），计算 KPI，并可调用原 `run_ac_check`。价格绑定同时更新场景价格及显式外网价格，避免外网旧价格盖住新数据；气象更新默认/已有区域温度；碳因子更新实际区域的平均/边际数据；负荷更新目标 DC 的 interactive_mw；设备参数/分段功率曲线/热性能在求解前真正覆盖目标设备并重新校验。

`cost` 明确表示把运行目标的碳权重设为0，不能拿原预设的非零碳权重结果与它直接比较。加权碳成本需要显式权重；不把大权重成本目标冒充“纯碳最优”。原年度、多目标/Pareto 工具未删改。

### 编辑、过期与追溯
签出总是创建独立会话副本。原拓扑/参数表/配置构建器/对话修改会话，不改版本；回到项目页显式“写回草稿”。写回会实体化当前模型，并解除草稿中的旧绑定，避免库参数再次盖掉手工修改；旧绑定与基版本记录进入 provenance，历史版本仍保存原内容。需要继续参数化绑定时显式重新绑定。

任一会话模型改变时旧结果失效（含旧 KPI、对比、拓扑结果缓存），顶部显示未写回/结果过期；新求解记录实际输入指纹后才恢复新鲜状态。项目会话的非法参数/拓扑修改会回滚，旧式会话保留原有编辑行为但仍需发布前严格校验。草稿 JSON 的未保存编辑跨页保留，切换场景/项目会确认。

查看历史任务时从存储中的完整模型与结果创建新的展示副本，而非借用当前会话。服务重启后也能恢复 DataFrame、热指标和调度结果，继续进入三级运行。重跑创建新任务，使用原冻结输入，不重新解释资源库；若代码更新，实际执行 code hash 与冻结时 hash 分别保留，不保证跨代码版本数值一致。

## 校验矩阵
- 设备正容量、PUE、储能效率/SOC/备用比例，温度顺序、热容量/COP/冷却边界、分段功率曲线单调与0~1覆盖。
- 母线端点、电压等级、线路/变压器、无源负荷孤岛，任务窗口与资源余量；静态通过仍可能动态不可行，求解失败会记录 failed 而不是返回旧结果。
- 24点有限数值、正确单位、地点/年份/IANA时区/零点/60分钟步长一致；可选逐点 timestamps 无重复/跳点。不静默补值、转换币种、截断全年序列或推断缺失连接。
- 设备库首批支持数据中心（含热参数/分段功率）和储能的性能模型；其他设备仍在场景 JSON/模板中维护，不伪称已纳入独立通用设备库。

## 数据与结果真实性边界
首批种子包括明确合成的电价/碳/负荷/设备参数，以及从既有公开缓存提取的中卫、韶关、乌兰察布 `2024-07-01` Open-Meteo ERA5 温度，记录原 URL、文件路径与 SHA256。再分析温度不是机房现场测点；公开项目等值场景不是原工程完整设计图。首批气象通用绑定为干球温度，其余湿度/风光沿场景已有输入。负荷映射和结算仍受原公开基准已知局限约束，尤其需求响应基线尚不能用于正式结算。

本轮版本化任务是24小时运行调度纵向闭环；原8760/投资多目标入口保留，尚未统一包装为本次版本任务。market仍为原沙盘，无真实交易接口/自动下单。无用户/权限/多租户系统，服务应仅在可信本地网络使用，不能直接当作生产公网运营平台。

## 修复过程中发现的额外缺陷
单母线、无支路的有效网络在原引擎结果汇总 `max(empty)` 抛错；交流校核无线路/无变压器的最大负载率可能是NaN并错误影响 loading_ok。已只对空集合定义0负载率，不改变有支路公式，新增真实求解与AC回归。A01电池方向修复保持，纳入全量回归。

## 用户路径
1. **新项目**：①资源与建模 → 项目与场景 → 填项目名创建 → 选择模板并填场景名/时间轴 → 从模板新建。
2. **绑定公开气象**：数据与设备模型库选对应地点的公开气象，按资源 axis 设置场景时间轴 → 项目页添加绑定 → 校验 → 发布不可变版本。
3. **修改模型**：签出草稿 → 原拓扑/参数/配置构建器修改 → 顶部显示未保存/旧结果过期 → 项目页“当前会话模型→写回草稿” → 发布新版本。旧版任务不变。
4. **运行**：顶部选场景及已发布版本 → ②仿真优化/版本化仿真任务 → 选目标与求解配置 → 创建冻结任务 → 运行所选任务。
5. **追溯**：选任务查看完整输入/来源/hash/代码与求解器标识 → 查看当时模型与结果 → 原结果页/拓扑/三级运行；可下载任务JSON与原输入产物，或按原快照创建新重跑。
6. **旧会话**：保持原使用方式；若需纳管，先选项目，再“将当前旧会话导入为场景”，不会自动篡改历史。

### 参数来源和混合数据说明
绑定版本不仅保存在任务JSON里，也会进入原“参数透明核对”页面的逐字段来源，显示资源名、版本、ID、原来源和适用工况，避免误标成引擎默认值。场景note会明确哪些信号被新版覆盖，并提示未绑定的风光/任务等仍沿原预设，因此三个验证项目是“公开温度叠加原等值场景”的混合输入测试，不声称整套输入来自同一自然日现场计量。

## API 主要路径（本地）
| 操作 | HTTP |
|---|---|
| 目录/项目 | GET `/api/foundation/catalog`；POST `/projects`；PATCH `/projects/{id}` |
| 建场景/改草稿 | POST `/scenarios`；PATCH `/scenarios/{id}/draft`（必填expected_revision） |
| 校验与发布 | POST `/scenarios/{id}/validate`；POST `/scenarios/{id}/publish`（expected_revision） |
| 读历史版本 | GET `/versions/{id}`，无覆盖API |
| 模板/通用资源 | POST `/templates`；POST `/library`；GET `/library/{id}`；资源修订传previous_id追加新版本 |
| 旧会话纳管 | POST `/sessions/{sid}/import` |
| 签出与写回 | POST `/scenarios/{id}/checkout`（可选version_id）；POST `/sessions/{sid}/save-draft`（expected_revision） |
| 上下文/过期 | GET `/sessions/{sid}/context` |
| 创建/运行任务 | POST `/tasks`（version_id,objective,solver）；POST `/tasks/{id}/run` |
| 追溯/重跑/结果副本 | GET `/tasks/{id}`；POST `/tasks/{id}/rerun`；POST `/tasks/{id}/open` |
上表省略的统一前缀均为 `/api/foundation`。任务运行是本地同步HTTP调用，页面显示运行中；失败只记录失败，不回退使用旧计划。后台队列、远程执行/多人权限、全类型设备独立建库不在本轮交付范围。
